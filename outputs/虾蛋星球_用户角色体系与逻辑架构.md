# 虾蛋星球 - 用户角色体系与逻辑架构设计

## 一、用户角色体系

### 1.1 四种核心角色

| 角色 | 标识 | 权限范围 | 主要功能 |
|------|------|----------|----------|
| **普通用户** | `user` | 浏览、收藏、评论 | 发现工具、收藏喜欢、发表评论 |
| **开发者** | `developer` | 普通用户权限 + 产品管理 | 入驻申请、录入产品、编辑产品、智能推广、查看数据 |
| **星推官** | `promoter` | 普通用户权限 + 推广功能 | 生成推广链接、查看点击数据、赚取佣金、提现 |
| **管理员** | `admin` | 全部权限 | 用户审核、内容审核、数据管理、平台配置 |

## 六、数据库表设计

### 6.1 核心表结构

```sql
-- 用户资料表
profiles {
  id: uuid (PK, FK -> auth.users)
  username: text
  avatar_url: text
  bio: text
  role: text ['user', 'developer', 'promoter', 'admin']
  phone: text
  phone_verified: boolean
  created_at: timestamp
}

-- 开发者申请表（用于审核流程）
developer_applications {
  id: uuid (PK)
  user_id: uuid (FK -> profiles)
  company_name: text
  contact_name: text
  contact_phone: text
  portfolio_url: text
  status: text ['pending', 'approved', 'rejected']
  applied_at: timestamp
  reviewed_at: timestamp
  reviewed_by: uuid (FK -> profiles)
}

-- 星推官表
promoters {
  id: uuid (PK)
  user_id: uuid (FK -> profiles)
  commission_rate: decimal
  total_earned: decimal
  total_withdrawn: decimal
  status: text ['active', 'suspended']
  joined_at: timestamp
}

-- 工具表
tools {
  id: uuid (PK)
  name: text
  description: text
  icon_url: text
  developer_id: uuid (FK -> profiles)
  status: text ['pending', 'approved', 'rejected']
  view_count: int
  jump_count: int
  created_at: timestamp
}

-- 推广链接表
promotion_links {
  id: uuid (PK)
  tool_id: uuid (FK -> tools)
  promoter_id: uuid (FK -> profiles)
  code: text
  click_count: int
  conversion_count: int
  commission_earned: decimal
  created_at: timestamp
}

-- 推广内容表（智能推广）
promotion_contents {
  id: uuid (PK)
  user_id: uuid (FK -> profiles)
  tool_id: uuid (FK -> tools)
  title: text
  content: json
  status: text ['draft', 'scheduled', 'published']
  created_at: timestamp
}
```

## 九、安全与权限控制

### 9.1 RLS 策略设计

```sql
-- profiles 表 RLS
• 所有人可查看公开信息
• 仅本人可修改自己的资料
• 管理员可查看和修改所有

-- tools 表 RLS
• 所有人可查看已审核通过的工具
• 开发者可查看和管理自己的工具
• 管理员可查看和管理所有工具

-- promotion_links 表 RLS
• 星推官可查看自己的推广链接
• 管理员可查看所有推广链接

-- promotion_contents 表 RLS
• 开发者可查看和管理自己的推广内容
• 管理员可查看所有推广内容
```

### 9.2 前端权限控制

```typescript
// 权限检查函数
function checkPermission(role: string, route: string): boolean {
  const permissions = {
    user: ['/', '/tool', '/profile', '/join'],
    developer: ['/', '/tool', '/profile', '/join', '/dashboard', '/promotion'],
    promoter: ['/', '/tool', '/profile', '/promoter'],
    admin: ['*'], // 所有权限
  };
  return permissions[role]?.includes(route) || role === 'admin';
}
```

## 十、总结

虾蛋星球的用户角色体系设计遵循以下原则：

1. **清晰的角色划分**：四种角色各司其职，权限边界清晰
2. **灵活的身份切换**：用户可同时拥有多个角色，随时切换
3. **流畅的升级路径**：从普通用户到开发者/星推官的升级流程简单明了
4. **完善的后台功能**：每个角色都有专属的功能后台
5. **严格的安全控制**：通过RLS和前端权限控制保障数据安全

这套体系能够支撑虾蛋星球的业务需求，为不同用户提供个性化的功能体验。
